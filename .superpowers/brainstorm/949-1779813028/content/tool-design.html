Tool-Design: Unified Search + Detail (5 Tools)

Ansatz B · async Python · AutoGen-kompatibel · PostgreSQL + Embedding-Suche

Tool 1 — Kernsuche
search_recipes(...) → list[RecipeSummary]
Parameter (alle optional kombinierbar):
NameTypFunktion
querystr | NoneFreitext → Embedding-Suche (z.B. "etwas Wärmendes")
meal_typestr | NoneFrühstück · Mittagessen · Abendessen · Snack · Dessert
seasonstr | NoneFrühling · Sommer · Herbst · Winter · ganzjährig
max_difficultyint | None1–5, filtert recipes.difficulty ≤ Wert
max_time_minint | Noneprep_time_min + cook_time_min ≤ Wert
max_caloriesfloat | NoneJOIN recipe_nutrition, calories_kcal ≤ Wert
allergen_tagslist[str] | NoneMuss-Tags: ["vegan","glutenfrei"] → JOIN recipe_tags
ingredient_nameslist[str] | NoneRezepte die mind. diese Zutaten enthalten
limitintMax. Ergebnisse (default 10)

Rückgabe: list[RecipeSummary] — id, name, description, meal_type, season, difficulty, total_time_min, cost_tier, allergen_tags, calories_kcal

Logik: Hat query → Embedding generieren → Kosinus-Ähnlichkeit auf recipe.description; dann SQL-Filter obendrauf. Kein query → reiner SQL-Filter.

Tool 2 — Volldetail
get_recipe_detail(recipe_id: str) → RecipeDetail

Lädt ein vollständiges Rezept inkl. aller Joins in einem Query.

Rückgabe: Alle Felder aus recipes + recipe_instructions (geordnete Schritte) + recipe_ingredients mit Zutatennamen + recipe_nutrition + recipe_tags

Typischer Agent-Flow: search_recipes() → IDs → get_recipe_detail(id) für das ausgewählte Rezept

Tool 3 — Zufallsempfehlung
get_recipe_suggestions(count?: int, meal_type?: str, season?: str) → list[RecipeSummary]

Zieht count zufällige Rezepte (default: 3), optional nach Mahlzeit-Typ und Jahreszeit gefiltert.

Use Case: "Was soll ich heute Abend kochen?" ohne konkrete Vorgaben — der Agent ruft dies auf wenn der Nutzer keine spezifischen Wünsche hat.

Tool 4 — Semantisch ähnliche Rezepte
find_similar_recipes(recipe_id: str, limit?: int) → list[RecipeSummary]

Findet Rezepte die einem bekannten Rezept semantisch ähnlich sind (über Description-Embedding).

Use Case: "Zeig mir mehr wie das" oder "Varianten von Rezept X"

Tool 5 — Zutatenliste
list_ingredients(recipe_id: str) → list[IngredientEntry]

Gibt nur die Zutatenliste zurück (name, amount, unit, preparation) — ohne Schritte/Nährwerte.

Warum separat: Vorratsschrank-Abgleich braucht keine Schritte, und das Tool bleibt schlank für zukünftige Erweiterungen (z.B. Einkaufsliste).

Datenstruktur

RecipeSummary (Listenansicht): id, name, description, meal_type, season, difficulty, total_time_min, cost_tier, allergen_tags, calories_kcal
RecipeDetail (Vollansicht): alle Summary-Felder + instructions (Liste), ingredients (Liste mit Mengen), nutrition (alle Nährwerte)
IngredientEntry: name, amount, unit, preparation
