Drei Ansätze für die Agent-Tool-Schicht

Alle Ansätze sind lesend + semantische Suche · AutoGen-kompatibel · async Python

A

Viele kleine Tools

8–9 spezialisierte Tools, jedes für genau eine Dimension.

  • search_recipes_by_name(query)
  • filter_recipes(meal_type, season, difficulty, …)
  • filter_by_nutrition(max_calories, min_protein, …)
  • find_by_ingredients(ingredient_names)
  • search_semantic(query)
  • get_random_suggestions(count, filters)
  • get_recipe_detail(id)
  • get_recipe_nutrition(id)
  • get_similar_recipes(id)

Pro

  • Jedes Tool maximal einfach
  • Gut testbar isoliert

Contra

  • Agent muss viele Calls kombinieren
  • Mehr Latenz (mehrere DB-Trips)
B

Unified Search + Detail ★ Empfehlung

5 Tools — ein mächtiges Such-Tool kombiniert SQL-Filter und semantische Suche, daneben Detail-Tools.

  • search_recipes(query?, meal_type?, season?, max_difficulty?, max_time_min?, max_calories?, allergen_tags?, ingredients?, limit?)
  • get_recipe_detail(id) — Schritte + Zutaten + Nährwerte
  • get_recipe_suggestions(count?, meal_type?, season?) — zufällig/saisonal
  • find_similar_recipes(recipe_id, limit?) — semantisch ähnlich
  • list_ingredients(recipe_id) — nur Zutatenliste (Vorratsschrank-ready)

Pro

  • Agent drückt komplexe Fragen in einem Call aus
  • Wenige Roundtrips → schneller
  • Natürliche Tool-Namen

Contra

  • search_recipes hat viele optionale Parameter
C

Discovery- + Detail-Layer

4 Tools — expliziter zweistufiger Fluss: erst entdecken, dann vertiefen.

  • discover_recipes(query, filters) → Kurzliste mit IDs
  • get_recipe(id) → vollständiges Rezept
  • get_similar(recipe_id) → ähnliche Rezepte
  • suggest(context_text) → kontextuelle Empfehlung

Pro

  • Sehr saubere API-Struktur
  • Spiegelt REST-Design wider

Contra

  • Immer mindestens 2 Calls nötig
  • Agent-Steuerung komplexer
